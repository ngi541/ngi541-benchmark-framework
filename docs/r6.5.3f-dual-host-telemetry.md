# R6.5.3f — Dual-host telemetry qualification

R6.5.3f freezes the telemetry contract used by the R6.5.3g stock-only planner
and later paired stock/NGI541 campaigns. It is a capability qualification, not
a performance claim.

## DUT (Darwin)

Required channels are system CPU load, process-tree cumulative CPU time and RSS,
selected network-interface counters, CPU temperature/thermal context, and AC
power state. `powermetrics` package power is collected when the platform exposes
it. The field is named `package_power_w_estimate`: Apple documents these values
as estimates, so they are valid only as a secondary **same-machine paired A/B**
metric, not as calibrated wall power or for cross-device comparisons.

When package power is available, the framework can integrate it over the sample
window as estimated joules. Later workload stages can therefore derive an
`estimated_energy_j_per_GiB` metric alongside the more direct
`process_cpu_seconds_per_GiB` metric.

## Load generator (Linux / Raspberry Pi)

Required channels are total CPU utilization, per-core CPU utilization, per-core
frequency, SoC temperature, firmware `get_throttled` state, process cumulative
CPU time/RSS, interface bytes/packets/errors/drops, UDP input errors and load
average. PMIC temperature is recorded opportunistically.

Raspberry Pi voltage telemetry is **not** converted to watts. The platform does
not provide a canonical onboard total-current measurement suitable for this
benchmark. Total load-generator watts therefore remain unavailable unless a
future external sensor provider (USB-C meter, INA-class monitor, lab PDU, etc.)
is explicitly configured and calibrated.

## Power/energy role in NGI541 claims

Power is useful, but secondary. The primary resource-efficiency metric remains
CPU seconds per transferred GiB; on PMU-capable R7 hosts this can be strengthened
with cycles/byte and related hardware counters. Same-host package-power estimates
can add estimated joules/GiB and average watts, which is useful if NGI541 lowers
CPU work for the same encrypted scientific goodput. Temperature by itself is not
an efficiency metric; it is mainly a validity/control signal for throttling and
thermal-state comparability.

## Qualification command

```bash
./scripts/experiment.sh dual-host-telemetry \
  --config benchmark/configs/r6.5.3f-pi-mac-dual-host-telemetry.json
```

The qualification resolves the frozen R6.5.3c network evidence, R6.5.3b loadgen
runtime and R6.5.3e transport-security gate, uses their exact interfaces/SSH
identity, samples both hosts at one-second cadence, checks process-telemetry
providers with harmless `sleep` processes, and records a simple SSH midpoint
clock-offset estimate for later timeline alignment.
