# R6.5.3c — Network Evidence Resolver and Envelope Derivation

## Scope

R6.5.3c converts repeated R6.5.1 path measurements into a frozen, deterministic
network input for the later scientific HTTP/3 transport planner. It does not
run NGINX, curl or h2load and it does not make an NGI541 performance claim.

## Evidence contract

The canonical configuration references the existing R6.5.1 qualification
rather than duplicating ping/iperf parameters. A candidate observation is
eligible only when it is COMPLETE, has the same semantic network-definition
SHA-256 and passes its `artifacts.sha256` integrity inventory.

Strict path compatibility (`strict-path-v1`) fingerprints:

- topology classification;
- HTTP/3 response direction;
- local system, address, interface, hardware port and gateway;
- remote system, address, configured address, interface and gateway;
- remote negotiated link speed, duplex and link-detected state.

Observed performance values are deliberately excluded from the fingerprint.
They are evidence to aggregate, not criteria for deciding whether a run is
compatible.

The newest matching COMPLETE observation establishes the current topology.
Older topology groups are not mixed into the selected set. With the canonical
configuration the latest three compatible observations are frozen.

## Automatic collection

If fewer than three observations exist for the current topology,
`network-evidence` invokes the referenced R6.5.1 qualification automatically.
All missing observations in one resolver invocation reuse one SSH ControlMaster
session. If a newly collected observation changes the strict topology
fingerprint, collection stops and the resolver fails rather than mixing paths.

## UDP qualification rule

R6.5.1 originally reports the highest UDP requested rate satisfying the loss
limit. R6.5.3c deliberately recomputes its own stricter safe point from the raw
normalized UDP rows. A point qualifies only when:

```text
loss_percent <= 0.1
achieved_mbps / requested_mbps >= 0.95
```

Among qualifying points the highest requested rate is selected for that
observation. Both requested and achieved rates are retained.

If a selected observation has no qualifying UDP point, derivation fails. The
resolver does not discard that run based on the measured result because doing
so would bias the envelope upward.

## Conservative envelope

For the DUT-to-loadgen direction:

```text
tcp_floor = min(best TCP throughput from every selected observation)
udp_safe_floor = min(safe UDP achieved throughput from every selected observation)
service_envelope = min(tcp_floor, udp_safe_floor)
```

The service envelope is therefore a conservative empirically qualified local
path rate. It is not synonymous with reserved or guaranteed network capacity.
Later R6.5 stages may project scientific workloads to fractions of this
envelope without changing the scientific workload definitions themselves.

## Output

```text
qualifications/network-evidence/<evidence-id>/
├── config.json
├── inputs/
│   └── network-qualifications.json
├── processed/
│   ├── network-envelope.json
│   ├── summary.json
│   └── SUMMARY.md
└── artifacts.sha256
```

`network-envelope.json` contains no resolver wall-clock timestamp or generated
output ID. Its content is derived only from the frozen observations and policy,
so identical inputs produce the same semantic envelope SHA-256.

## Canonical command

```bash
./scripts/experiment.sh network-evidence \
  --config benchmark/configs/r6.5.3c-pi-mac-network-evidence.json
```

Use `--bootstrap` only when an automatically collected R6.5.1 observation may
need iperf3 provisioning.
