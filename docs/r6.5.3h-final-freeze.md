# R6.5.3h — lifecycle, resume, and final freeze

R6.5.3h does not collect new performance measurements.  It validates the
complete R6.5.3 evidence chain, freezes exact artifact identities, and emits the
contract that R6.5.4 must consume without adaptive modification.

## Scope

The stage resolves and pins the COMPLETE artifacts produced by R6.5.3b-g:

- network evidence and deterministic DUT→loadgen service envelope;
- pinned remote HTTP/3 curl + h2load runtime;
- deterministic scientific corpus and profile registry;
- HTTP/3/TLS 1.3 security/functional transport qualification;
- dual-host telemetry capability qualification;
- stock-only derived workload plan.

R6.5.3h makes no stock-vs-NGI541 performance claim.

## Frozen lifecycle

The final-freeze command persists this lifecycle:

```text
CREATED
  -> INPUTS_RESOLVING
  -> INPUTS_FROZEN
  -> PROFILES_VALIDATED
  -> RUNTIME_READY
  -> SECURITY_VERIFIED
  -> NETWORK_ENVELOPE_FROZEN
  -> CORPUS_READY
  -> TELEMETRY_READY
  -> STOCK_PROBING
  -> PLAN_DERIVED
  -> PLAN_FROZEN
  -> VALIDATED
  -> COMPLETE
```

Any active phase may enter `FAILED`.  Re-running the same command resumes from
`last_completed_state`; once `INPUTS_FROZEN` has been reached, resume uses the
pinned artifact paths and hashes instead of re-resolving newer evidence.

## Cross-artifact validation

The freeze rejects a chain in which any linkage has drifted.  In particular:

- transport-security must reference the pinned network evidence, loadgen runtime
  and scientific corpus;
- telemetry must reference the pinned network evidence, loadgen runtime and
  transport-security qualification;
- workload-planner must reference the pinned network, runtime, corpus, security
  and telemetry artifacts;
- the workload plan must still be stock-calibrated, contain the exact
  3-profile × 2-service-target × 2-worker = 12 condition cross-product, and
  retain the candidate-bias prohibition;
- security remains HTTP/3-only, TLS 1.3, `TLS_AES_128_GCM_SHA256`, peer-verified
  and 0-RTT-disabled;
- artifact inventories are re-verified where the producing stage exposes one.

The R6.5.3b loadgen runtime predates the local `artifacts.sha256` convention, so
its local summary SHA and the remote curl/h2load binary SHA values are pinned
instead.  R6.5.3g already verified the remote h2load SHA before deriving the
plan.

## Final R6.5.4 execution contract

`processed/final-manifest.json` explicitly freezes:

- exact stock and `ngi541-direct` binary/library SHA-256 values;
- exact R6.5.3 artifact roots, summary hashes and available inventory hashes;
- exact workload-plan ID and semantic SHA-256;
- the requirement that both variants consume the same frozen plan;
- prohibition of adaptive replanning or candidate-variant tuning;
- prohibition of metric-dependent retry and metric-dependent outlier deletion;
- qlog disabled by default for performance execution while h2load JSON QUIC
  metrics remain required.

This is the boundary between qualification/planning and R6.5.4 paired
measurement.

## Output

```text
qualifications/final-freeze/<freeze-id>/
├── definition.json
├── state.json
├── inputs/
│   └── resolved-inputs.json
├── processed/
│   ├── final-manifest.json
│   ├── summary.json
│   └── SUMMARY.md
└── artifacts.sha256
```

`state.json` is intentionally excluded from `artifacts.sha256` because it is
mutable while the lifecycle advances.  All immutable definition/input/final
artifacts are covered by the final inventory.

## Command

```bash
./scripts/experiment.sh final-freeze \
  --config benchmark/configs/r6.5.3h-pi-mac-final-freeze.json
```

Re-running after `COMPLETE` with byte-identical resolved inputs reuses the same
frozen bundle.  Re-running after a failure resumes the incomplete bundle from
its last completed phase.
