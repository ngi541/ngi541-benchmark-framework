# R6.5.3a — Scientific Profile Registry

R6.5.3a introduces environment-independent scientific workload definitions for the
NGI541 secure scientific transport evaluation framework. It intentionally contains
no SSH, NGINX execution, network planning, or performance comparison logic.

## Profiles

- `clas12-event-stream-v1.json` — a representative 32 KiB event-scale workload
  derived from published CLAS12 DAQ rates and event-size observations. The 32 KiB
  value is a reproducible representative payload, not a claim that all CLAS12
  events have one exact size.
- `lcls-detector-frame-v1.json` — a fixed 10,000,000-byte detector frame at the
  published native rate of 120 frames/s (1.2 GB/s).
- `hacc-multifile-dataset-v1.json` — the published HACC L380 logical dataset:
  19,260 files, 4,442,781,786,482 bytes, 211 directories and the complete
  order-of-magnitude file-size histogram used by the Petascale DTN work.

## Separation of concerns

A scientific profile defines what scientific data is represented. It must not define
where or how a benchmark is executed. Topology, bandwidth, workers, connections,
streams, target goodput, server addresses and implementation variants are rejected
as profile fields.

Execution intensity is derived later by R6.5.3 from network evidence and stock-only
qualification. Object semantics remain unchanged when the environment changes from
Pi/Mac to a wired host or CloudLab.

## Content model

Canonical performance content is deterministic surrogate data generated from a
SplitMix64 namespace. Scientific object sizes, rate semantics and distributions are
source-derived; the bytes themselves remain reproducible and independent of access
to external scientific data archives.

## Registry identity

Each profile is canonically serialized and SHA-256 hashed. Registry loading enforces
`<profile_id>-v<profile_version>.json` filenames, unique identities and deterministic
registry manifests. These hashes become frozen inputs to later transport
qualification and workload planning stages.

## R6.5.3a Definition of Done

- three source-grounded versioned scientific profiles;
- strict stdlib validation with no new Python dependency;
- environment/execution leakage rejected;
- CLAS12 representative-event consistency checked;
- LCLS frame-rate/data-rate arithmetic checked;
- HACC histogram continuity and count conservation checked;
- deterministic per-profile and registry SHA-256 identity;
- unit-test coverage for valid profiles and semantic failures.
