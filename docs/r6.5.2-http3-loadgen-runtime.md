# R6.5.2 — reproducible HTTP/3 load-generator runtime

R6.5.2 provisions an isolated, version-pinned HTTP/3 curl stack on the Raspberry Pi load generator. It does not replace `/usr/bin/curl` and it does not yet execute the NGINX comparison workload.

Pinned stack:

- OpenSSL 3.6.4
- nghttp3 1.18.0
- ngtcp2 1.25.0
- curl 8.22.0

The stack matches the client versions used in the historical local C2.1 environment where practical. Source archives are SHA-256 pinned. The runtime is installed below the remote user's home directory in a directory keyed by the semantic runtime-definition hash.

The command is:

```bash
./scripts/experiment.sh loadgen-runtime \
  --config benchmark/configs/r6.5.2-pi-http3-loadgen.json \
  --bootstrap
```

`--bootstrap` is only needed when build prerequisites are missing. On Debian 11/Bullseye it uses the Debian archive through an isolated temporary APT source and does not rewrite the host's normal APT configuration.

Definition of done:

- pinned source archives pass SHA-256 verification;
- all four components build under the isolated prefix;
- the resulting curl advertises `HTTP3`;
- the curl binary SHA-256, `curl --version`, architecture, compiler version and dynamic linkage are recorded locally;
- a subsequent run with the same definition reuses the already-qualified runtime instead of rebuilding it.

Actual Pi -> Mac QUIC/HTTP/3 connectivity is R6.5.3, not R6.5.2.
