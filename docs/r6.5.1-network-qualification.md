# R6.5.1 — network-path qualification

R6.5.1 characterizes the path between a remote load generator and the DUT before
HTTP/3 performance is measured. It is deliberately separate from the HTTP/3
campaign: `iperf3` is a calibration instrument, not the QUIC/HTTP/3 workload
client.

The first topology is:

```text
Raspberry Pi (Linux/aarch64, loadgen)
        |
        | eth0, 1 GbE
        v
     LAN switch/AP
        |
        | Wi-Fi
        v
Mac (Darwin/x86_64, DUT)
```

This is classified as `mixed-wired-wifi`. Results are network-characterization
only and are not NGI541 performance claims.

## One-command qualification

```bash
./scripts/experiment.sh network-qualify \
  --config benchmark/configs/r6.5.1-pi-mac-network.json \
  --bootstrap
```

`--bootstrap` is optional. When requested it installs missing `iperf3` on the
supported endpoints: Homebrew on the local Darwin controller and apt on the
remote Debian/Linux peer. The first SSH connection may request the remote login
password or key confirmation once; a temporary SSH ControlMaster is then reused
for the rest of the qualification.

Without `--bootstrap`, missing dependencies fail before measurements and no
package-manager changes are made.

## Measurements

The qualification records:

- local and remote OS/CPU/network inventory;
- local route, selected interface and local address;
- remote route, interface, negotiated Ethernet speed/duplex when `ethtool` is
  available;
- bidirectional ping RTT and packet loss;
- bidirectional TCP capacity with one and four parallel streams;
- bidirectional UDP sweeps using 1200-byte datagrams at configured rates;
- UDP loss and jitter;
- raw command output, normalized summary, config identity and SHA-256 artifact
  inventory.

HTTP/3 response payloads flow from the DUT to the load generator. With the
current role assignment (`local=dut`, `remote=loadgen`) that is the
`local-to-remote` direction. The summary marks this direction explicitly.

## Output

Each invocation creates a new immutable qualification record under:

```text
qualifications/network/<qualification-id>/
├── config.json
├── raw/
│   ├── commands/
│   ├── iperf3-server.stdout.log
│   └── iperf3-server.stderr.log
├── processed/
│   ├── summary.json
│   ├── reference.json
│   └── SUMMARY.md
└── artifacts.sha256
```

The UDP reference is the highest tested configured rate whose observed loss is
at or below the reporting threshold. It is a path reference, not a claim that
QUIC will achieve the same rate.

## Future reuse

The result schema intentionally distinguishes local and remote endpoint
providers. R6.5 uses `local` + `linux-ssh`; a later wired Windows host can add a
Windows/OpenSSH provider without changing the normalized topology, ping, TCP or
UDP result schema. CloudLab can likewise use Linux SSH endpoints with different
network interfaces.

`processed/reference.json` is the compact machine-readable path-capacity artifact
intended for R6.5.3/R6.5.4 HTTP/3 campaigns. It keeps the measured network
ceiling separate from the HTTP/3 workload and lets later analysis flag a result
whose payload goodput approaches the qualified path capacity.
