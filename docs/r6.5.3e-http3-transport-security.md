# R6.5.3e — TLS/HTTP/3 security gate and functional scientific transport smoke

R6.5.3e is a functional/security qualification only.  It does not measure or
compare performance.

## Inputs

The qualification resolves and freezes:

- the latest COMPLETE R6.5.3c network evidence matching the configured
  definition;
- the latest COMPLETE R6.5.3b ARM64 load-generator runtime matching its pinned
  definition;
- the deterministic R6.5.3d scientific corpus;
- the SHA-256 pinned stock and NGI541-direct NGINX binaries and NGI541 runtime
  library.

The DUT address is taken from the frozen network-evidence topology rather than
hard-coded into the transport definition.

## Security contract

The server and reference client are constrained to:

- HTTP/3 only;
- TLS 1.3 only;
- `TLS_AES_128_GCM_SHA256` only;
- peer identity verification using an ephemeral qualification CA;
- 0-RTT disabled;
- no HTTP/2 or HTTP/1.1 fallback.

The test CA and server leaf are generated per qualification.  Only public
certificates are retained as evidence; private keys remain in the temporary
runtime and are removed after the qualification.

## Scientific smoke objects

One deterministic object is transferred from each frozen scientific profile:

- CLAS12 event stream: stream index 0, 32,768 bytes;
- LCLS detector-frame stream: frame index 0, 10,000,000 bytes;
- HACC multi-file dataset: the first deterministic object in histogram bucket 6
  (1–10 MB normalized bucket).

The objects are generated from the frozen SplitMix64 corpus recipes.  The Pi
load generator downloads each object and computes SHA-256 locally; the result
must exactly match the source object hash.

The HACC selector is intentionally a functional smoke selector, not an HACC
coverage model.  Full, deterministic-stratified and time-window HACC coverage
remain defined by R6.5.3d for later workload planning.

## Client roles

Pinned curl is the authoritative security and content-correctness gate.  It
uses `--http3-only`, explicit TLS 1.3 limits, the pinned TLS 1.3 cipher suite,
`--cacert`, and hostname resolution to the DUT data address.  Success requires:

- HTTP version 3;
- HTTP status 200;
- certificate verification result 0;
- exact expected byte count;
- exact downloaded SHA-256.

Pinned h2load is then run once per variant with one connection and one stream to
prove that the R6.5.3b HTTP/3 load-generator path can reach the same private
server.  h2load is not the authoritative certificate-verification assertion;
that assertion belongs to the curl gate.

## Acceptance

R6.5.3e is COMPLETE only if both variants pass all three curl
security/correctness transfers and the one-shot h2load HTTP/3 transport probe.
No metric-dependent retry, concurrency tuning, rate tuning or performance claim
is permitted in this milestone.
